# 로비·방 채팅 화면

2026-09-08 로컬 A-08 구현. [서버 규격](../../backend/docs/chat-delivery.md)의 HTTP 전송과
수신 전용 WebSocket을 사용한다. D01 21쪽 8절과 목업의 로비 오른쪽·방 정보 아래 배치를
참고했다. 과거 대화 조회·영구 저장·AI 분석을 추가하지 않는다.

## 화면과 연결

- Lobby는 접속 상태 확인 후, Room은 게임 상태 Snapshot으로 본인의 연결을 확인한 후 채팅을 연다.
- `ChatStream`은 `SnapshotStream`과 별개다. `chat.ready` 이후 범위·발신자·텍스트를 검사한
  `chat.message`만 표시한다. 채팅 오류는 게임 소켓·Ready·Vote·방장을 변경하지 않는다.
- 화면에 최근 100개만 유지한다. 이는 화면 메모리 상한이지 서버 보관 정책이 아니다.
  연결/신원/참여 범위가 바뀌면 목록을 비우며 브라우저 저장소에 보관하지 않는다.
- 같은 방의 대기·게임·결과에서는 채팅 위치를 유지한다. 방에서 랭킹을 열면 연결은 유지하되
  입력과 화면 밖 알림 읽기를 끈다. 게임 상태 HTTP 재조회만으로 채팅 연결을 다시 만들지 않는다.
- 창 focus/visibility 복귀 때도 같은 신원·범위의 화면과 연결을 유지한다. 인증 재확인 중에는 입력을
  잠그고, 만료·다른 신원·확인 실패에는 이전 채팅을 지운다. 단순 focus를 신규 채팅 입장으로 취급하지 않는다.
- 채팅 연결 실패는 명시적 다시 연결 버튼으로 복구한다. 15초 안에 초기 응답이 없으면
  채팅만 중단한다. 끊긴 동안의 메시지를 복구했다거나 전달 완료로 표시하지 않는다.

## 입력·전송

- 서버와 같은 공백 제거 후 Unicode code point 1~200자다. 이모지 200개도 허용하며
  단독 surrogate는 거부한다. IME 조합 Enter는 전송하지 않고 Shift+Enter는 줄바꿈이다.
- 기존 `ApiClient`의 Cookie·CSRF·same-origin/no-store를 사용한다. 전역 게임 작업 상태를
  갱신하지 않고 채팅 내부에서만 중복 전송을 막는다. 전송 중 입력은 읽기 전용으로 두어 초점을 유지한다.
- 서버 Receipt 확인 후 입력을 비운다. 실제 메시지는 WS 수신으로만 표시하고 임시 성공 말풍선을 만들지 않는다.
  Receipt는 읽음 확인이 아니다. 실패/응답 불명확 시 입력을 보존하며 자동 재전송하지 않는다.
- 화면 이동·채팅 단절 때 진행 중 요청을 취소하고 늦은 응답이 다음 화면의 입력을 지우지 않게 한다.
  취소가 서버 전송 취소를 보장하지는 않으므로 결과 불명확 안내를 표시한다.
- 이전 메시지를 읽는 중에는 자동 스크롤하지 않고 새 메시지 버튼을 제공한다.
  대화 목록 높이를 고정하고 텍스트를 React 문자열로 렌더링한다. HTML은 실행하지 않는다.

- `src/chat/chat.test.tsx`: 16 PASS. 정규화·수신 검사·중복/상한·초기 응답/시간 초과·종료 코드·
  오래된 수신 폐기·CSRF·전송 중복·IME·이모지·실패/범위 이동·숨김·스크롤을 확인했다.
- Frontend 전체 224 PASS/15 files. TypeScript, OpenAPI 생성 일치, Vite Build PASS.
- `e2e/ui-feedback.spec.ts`: 12개 시나리오 × 2회, 24 PASS/19.9초, 재시도 0.
  채팅 4개는 Lobby/Room × 1280/390px다. 입력 폭·패널 내부 버튼·전송 초점·줄바꿈·스크롤·
  높이 유지·채팅 장애 시 게임 연결/보드 보존을 확인하고 캡처를 직접 검토했다.
- 첫 캡처에서 공통 버튼의 width:100% 때문에 입력창이 좁아지는 문제를 수정하고
  입력 폭 100px 초과·버튼 패널 경계 검사를 추가했다. 기존 시험의 단일 소켓 가정과
  서버에서 이미 제거하는 후행 공백 모의 자료를 바로잡았다. 오류 검사를 완화하지 않았다.
- Browser 시험은 합성 HTTP/WS 자료다. 실제 Backend와 브라우저를 연결한 전체 흐름,
  실제 Redis·다중 Replica·Gateway 동작, 사용자 화면 수용을 완료했다는 의미가 아니다.
  사용자 시험 서버는 재시작하지 않았다. 최신 Backend 적용은 별도 확인이 필요하다.

Raw 캡처는 `frontend/test-results/`에 생성되며 자동으로 Git에 포함하지 않는다.
