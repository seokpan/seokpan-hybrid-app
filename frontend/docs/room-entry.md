# 방 생성·입장 모달

[App #56](https://github.com/seokpan/seokpan-app/issues/56)의 A-08 화면 보완이다.
D01의 방 생성·입장 규칙과 제공된 01-3A/01-3B 목업을 따른다. 공개 여부·비밀번호·정원·
최소 Ready·투표 시간의 기존 API/서버 검증은 변경하지 않는다.

## 동작

- 로비 목록을 유지한 채 모달을 연다. Member만 생성 가능하며 공개 방도 입장 확인 모달을 사용한다.
  비공개 방에는 방 이름·현재 인원·비밀번호를 표시하고 진행 중이면 관전자 입장을 안내한다.
- 기본값은 정원 100명·최소 Ready 4명·15초다. 정원 2~100, 최소 Ready 2~정원,
  투표 시간 5/10/15/30초를 유지한다. 이미지의 예시 수치를 별도 규칙으로 사용하지 않는다.
- 닫기/취소/Escape는 요청을 보내지 않으며 다시 열면 새 입력으로 시작한다. 배경은 native
  modal로 조작을 차단한다. Tab/Shift+Tab은 모달 내부에서 순환하고 닫으면 원래 버튼으로 복귀한다.
  그 방이 사라지거나 버튼이 비활성화됐다면 로비 제목으로 초점을 보낸다.
- 요청 중에는 중복 제출·입력 변경·닫기를 잠근다. 비밀번호는 전송 후 입력창에서 지우고
  나머지 설정은 같은 사용자에게 실패 안내와 함께 남긴다. 비밀번호·CSRF를 Browser 저장소에 넣지 않는다.
- 방 입장 전 목록의 최신 `state_version`을 사용한다. 정원 마감·방 제거·목록 연결 상실 때는
  버튼뿐 아니라 submit 처리에서도 거절한다. 서버 응답을 확인하지 않고 입장 완료로 표시하지 않는다.

## 인증 재확인과의 관계

`SessionProvider.enterRoom`은 기존 명령 잠금·CSRF·Cookie 재확인을 그대로 사용한다.
`SessionGate`는 직접 시작한 방 생성/입장 요청 중에만 동일 사용자의 로비와 입력을 잠근 채
유지한다. 실패 후 같은 신원이 확인되면 해당 모달 안에 오류를 표시한다. 수동 재시도만 가능하며
네트워크 오류를 이유로 명령을 자동 재전송하지 않는다.

세션 만료·다른 사용자·방 참여 확인 결과는 기존 화면 분기를 따른다. 일반 인증 불확실 상태,
로그아웃·수동 재확인까지 로비를 계속 보이도록 확대하지 않는다. 게임 보드·Room 연결 복구,
서버의 방 생성/입장 권한, HTTP·WebSocket 경로는 변경하지 않는다.
